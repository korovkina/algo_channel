🟡 Продолжаем разбор. Сегодня жёлтая версия: в массиве могут быть отрицательные числа

Условие то же: найти идущие подряд элементы с суммой ровно `k`. Убрали ровно одну гарантию — что все числа неотрицательные.

📊 Материал среднего уровня

Сначала посмотрим, как именно ломается вчерашнее окно. Вот контрпример из двух элементов:

`nums = [-1, 1]`, `k = 1`

Ответ очевиден глазами: это `[1]`, второй элемент. А окно его не найдёт. Смотрите:

• Взяли `-1`, сумма `-1`. Она меньше `k`, сжимать нечего
• Взяли `1`, сумма `0`. Всё ещё меньше `k`, сжимать по-прежнему нечего
• Массив кончился, ответа нет

Окно сжимается только когда сумма превысила `k`. Здесь она не превысила ни разу, поэтому `-1` так и осталось в окне и испортило сумму. Вся вчерашняя логика держалась на монотонности: вправо — растёт, влево — падает. С отрицательными числами этой опоры нет, и двигать границы становится некуда.

Паттерн: префиксные суммы плюс хеш-таблица

Ключевая идея: перестаём двигать границы и начинаем считать. Префиксная сумма `S(i)` — это сумма всех элементов от начала до `i`. Тогда сумма любого отрезка от `l` до `r` равна `S(r) - S(l-1)`.

Нам нужен отрезок с суммой `k`, то есть `S(r) - S(l-1) = k`. Переставим: `S(l-1) = S(r) - k`.

Вот и весь алгоритм. Идём слева направо, на каждом шаге знаем текущую `S(r)` и спрашиваем: встречалась ли раньше префиксная сумма, равная `S(r) - k`? Если да, отрезок между той позицией и текущей даёт ровно `k`. Хеш-таблица отвечает на этот вопрос за константу.

Алгоритм:

1️⃣ Заводим таблицу и кладём в неё пару `0: -1` — пустой префикс до начала массива.
2️⃣ Идём по массиву, накапливаем текущую префиксную сумму.
3️⃣ Проверяем, есть ли в таблице `сумма - k`. Есть — ответ найден.
4️⃣ Записываем текущую сумму в таблицу, если такой там ещё не было.

```python
def find_prefix(nums, k):
    seen = {0: -1}          # префиксная сумма → её первый индекс
    total = 0

    for i, x in enumerate(nums):
        total += x

        if total - k in seen:
            return (seen[total - k] + 1, i)

        if total not in seen:   # храним только первое вхождение
            seen[total] = i

    return None
```

Проверим на нашем контрпримере `[-1, 1]`, `k = 1`:

• Позиция 0: префикс `-1`. Ищем `-2`, не нашли. Запомнили `-1`
• Позиция 1: префикс `0`. Ищем `-1` — есть, на позиции 0. Значит отрезок с позиции 1 по 1, это `[1]`

Сложность: `O(n)` времени, `O(n)` памяти. За универсальность платим памятью под таблицу.

Два момента, на которых спотыкаются:

Пара `0: -1` в начале не для красоты. Без неё потеряются ответы, начинающиеся с первого элемента: для них `S(l-1)` — это сумма пустого префикса, то есть ноль.

Проверку делаем до записи текущей суммы в таблицу. Если поменять порядок при `k = 0`, элемент найдёт сам себя и вернёт отрезок нулевой длины.
