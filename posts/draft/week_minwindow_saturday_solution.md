👨‍💻 Разбор недели: Minimum Window Substring целиком

Паттерн: скользящее окно + словарь частот

Собираем всё, что копили неделю. Задача: в строке `s` найти самое короткое окно, содержащее все буквы из `t` (с учётом повторов). Пример: `s = "ADOBECODEBANC"`, `t = "ABC"` → `"BANC"`.

Решение делится на два шага, ровно как мы и разбирали: сначала словарь частот, потом окно.

Шаг 1. Словарь частот — наш чек-лист требований.

```python
counter = {}
for char in t:
    counter[char] = counter.get(char, 0) + 1
# для t = "ABC" получаем {'A': 1, 'B': 1, 'C': 1}
```

Пока ничего нового. Но дальше начинается фокус, ради которого стоит дочитать.

Шаг 2. Окно, которое «списывает» со счётчика.

Идея хитрая и красивая: мы будем использовать тот же самый `counter` как индикатор нехватки. Едет правый указатель, встречает нужную букву — и мы уменьшаем её счётчик на единицу. Как будто вычёркиваем пункт из чек-листа: «эту букву в окно добавили, одной меньше искать».

```python
if s[r] in counter:
    counter[s[r]] -= 1
    if counter[s[r]] >= 0:
        found += 1
```

И вот здесь самое важное — что означает знак счётчика:

• `counter[c] > 0` — буквы `c` в окне пока не хватает, ещё нужно добрать.
• `counter[c] == 0` — набрали ровно столько, сколько требовалось.
• `counter[c] < 0` — набрали с избытком: букв больше, чем нужно (в строке `s` эта буква попадается чаще).

Теперь смотрите на условие `if counter[c] >= 0`. Мы прибавляем `found` (счётчик «сколько нужных букв закрыто») только когда счётчик после уменьшения не ушёл в минус. Почему? Потому что уход в минус значит «эта буква уже была закрыта, а сейчас просто лишняя копия» — она не приближает нас к цели, засчитывать её нельзя. Считаем только те буквы, что реально закрыли пункт чек-листа.

Когда `found` дорос до `len(t)` — в окне собраны все нужные буквы. Условие соблюдается. Пора сжимать:

```python
while found == len(t):          # окно полное — сжимаем слева
    if s[l] in counter:
        counter[s[l]] += 1      # возвращаем букву в «нужно найти»
        if counter[s[l]] > 0:   # ушли в плюс — значит этой буквы теперь не хватает
            candidate = s[l:r]
            if len(candidate) < min_len:
                result = candidate
                min_len = len(candidate)
            found -= 1          # пункт чек-листа снова открыт
    l += 1
```

Левый указатель выбрасывает буквы из окна и возвращает их счётчик обратно (`+= 1`). Пока счётчик остаётся `≤ 0`, буква была в избытке — выбросили лишнюю копию, окно всё ещё полное, можно сжимать дальше. А вот как только счётчик стал `> 0` — мы выкинули последнюю нужную копию, комплект рассыпался: фиксируем длину окна как кандидата в ответ и уменьшаем `found`. Условие сломалось — снова черёд правого.

Ровно то правило из четверга: правый расширяет, пока не соберём комплект; левый сжимает, пока комплект держится.

И обещанный лайфхак — зачем `s = s + '*'`.

В самом начале авторского кода строка удлиняется на один символ:

```python
s = s + '*'
```

Звёздочка — это буква, которой точно нет в `t`, приклеенная в конец. Зачем? Представьте, что искомое окно упирается в самый конец строки (как `BANC` в нашем примере — оно кончается на последнем `C`). Без «фиктивного» хвоста правый указатель дошёл бы до конца строки — и цикл завершился бы, не успев сжать это последнее окно слева. Ответ потерялся бы.

Я проверила это на живом коде: убираешь звёздочку — и на примере `"ADOBECODEBANC"` вместо `"BANC"` получаешь неверный `"ADOBEC"`. Звёздочка даёт правому лишний холостой шаг за край, чтобы внутренний цикл сжатия точно отработал для последнего окна.

Узнаёте приём? На прошлой неделе мы приклеивали фиктивный `dummy`-узел перед головой списка — по той же причине: чтобы не разбирать краевой случай отдельной веткой. Здесь фиктивный символ в конце строки играет ту же роль. Это не красота ради красоты — это минус один источник багов и минус один `if`.

Собранное решение (авторский код, прогнан на всех тестах LeetCode):

```python
class Solution:
    def minWindow(self, s: str, t: str) -> str:
        result = ""
        counter = {}
        s = s + '*'                       # фиктивный хвост для последнего окна
        min_len = len(s)                  # старт минимума — с максимума
        for char in t:
            counter[char] = counter.get(char, 0) + 1

        # пропускаем начало s до первой нужной буквы
        i = 0
        while i < len(s) and s[i] not in counter:
            i += 1

        l, r = i, i
        found = 0
        while r < len(s):
            while found == len(t):        # окно полное — сжимаем слева
                if s[l] in counter:
                    counter[s[l]] += 1
                    if counter[s[l]] > 0:
                        candidate = s[l:r]
                        if len(candidate) < min_len:
                            result = candidate
                            min_len = len(candidate)
                        found -= 1
                l += 1
            if s[r] in counter:           # расширяем справа
                counter[s[r]] -= 1
                if counter[s[r]] >= 0:
                    found += 1
            r += 1
        return result
```

Сложность: `O(m + n)` по времени (каждый указатель проходит `s` один раз, плюс построение словаря по `t`), `O(n)` по памяти на словарь — где `m = len(s)`, `n = len(t)`.
