❌ Частая ошибка: указатель убегает за границы

🐥 Материал для новичков

Ситуация с реального занятия. Кандидат решает задачу «есть ли в отсортированном массиве пара с суммой `target`», дубликаты нужно пропускать. Пишет уверенно:

```python
def has_pair_with_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return True
        if s < target:
            left += 1
            while nums[left] == nums[left - 1]:  # пропускаем дубликаты
                left += 1
        else:
            right -= 1
    return False
```

Выглядит разумно, на примере из условия работает. Интервьюер, не меняясь в лице: «а прогоните на `[2, 2, 2, 2]` и `target = 5`».

```text
IndexError: list index out of range
```

Что случилось: внешний цикл честно проверяет `left < right`, а вот внутренний — нет. На массиве из одних двоек условие `nums[left] == nums[left - 1]` истинно до самого конца, указатель проскакивает `right`, вылетает за массив — и все падает.

Как правильно: внутренний цикл повторяет граничное условие внешнего.

```python
while left < right and nums[left] == nums[left - 1]:
    left += 1
```

Общее правило: каждый цикл, который двигает указатель, обязан сам себя ограничивать. Если условие границы стоит только во внешнем цикле, а двигаете вы указатель еще и во вложенном — вы уже написали баг, просто тест для него пока не пришел. Это касается и пропуска дубликатов, и пропуска «лишних» символов в строках, и любых других вложенных сдвигов.

✏️ Упражнение: массив `[2, 2, 2, 2]`, `target = 4`. Что вернет исправленная версия и сколько шагов сделают указатели?
