🔴 Финал разбора. Красная версия: элементы не обязаны идти подряд

Условие меняется в одном месте: нам нужна подпоследовательность, а не подмассив. То есть элементы можно брать не подряд, пропуская любые, но сохраняя их порядок.

Почему прошлые два решения тут не работают

И окно, и префиксные суммы держались на одном и том же предположении: ответ — это непрерывный кусок массива. Окно двигало его границы, префиксы вычитали одну границу из другой. Как только элементы разрешено пропускать, само понятие границ теряет смысл: ответом может быть первый элемент вместе с последним, а всё между ними выброшено.

Считать тут больше нечего, придётся перебирать.

Паттерн: перебор с возвратом (backtracking), он же DFS по дереву решений

Ключевая идея: для каждого элемента отвечаем на один вопрос — берём или не берём. Два ответа на каждый из `n` элементов дают дерево из `2^n` вариантов, и мы обходим его в глубину.

Слово «возврат» — про то, что происходит после неудачной ветки: мы отменяем последний выбор и пробуем противоположный. В коде это одна строка `path.pop()`, и она же самая забываемая.

Алгоритм:

1️⃣ Идём по массиву с позиции `i`, накапливая текущую сумму и сам набор.
2️⃣ Сумма совпала с `k` — ответ найден.
3️⃣ Массив кончился — ветка неудачная, откатываемся.
4️⃣ Иначе пробуем две ветки: с элементом `i` и без него.

```python
def find_subseq(nums, k):
    path = []

    def go(i, total):
        if total == k and path:
            return True
        if i == len(nums):
            return False

        path.append(nums[i])            # ветка «берём»
        if go(i + 1, total + nums[i]):
            return True
        path.pop()                      # возврат: отменяем выбор

        return go(i + 1, total)         # ветка «не берём»

    return list(path) if go(0, 0) else None
```

Пройдём по `[3, 34, 4, 12, 5, 2]` при `k = 9`:

• Берём `3`, берём `34` — уже `37`, дальше эта ветка ничего не даст
• Откатываемся, берём `3`, пропускаем `34`, берём `4` — сумма `7`
• Пропускаем `12`, берём `5` — `12`, мимо. Откат
• Пропускаем `5`, берём `2` — сумма `9`. Ответ: `[3, 4, 2]`

Сложность: `O(2^n)` времени, `O(n)` памяти на стек рекурсии. Экспонента — это честная цена за перебор: при `n = 30` вариантов уже больше миллиарда.

Что сказать на собеседовании, если попали в эту версию

Скажите вслух, что задача превратилась в перебор подмножеств и что полиномиального решения в общем случае нет. Это не капитуляция, а верная классификация, и её от вас как раз ждут.

А дальше стоит спросить про ограничения. Если числа целые и неотрицательные, а `k` небольшое, задача становится классическим рюкзаком и решается динамикой за `O(n·k)`. Одно уточнение про входные данные — и экспонента превращается в полином.
