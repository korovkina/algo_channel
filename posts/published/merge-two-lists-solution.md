Разбор задачи про слияние двух связных списков из прошлого поста

Паттерн: два указателя + dummy-узел (нода-пустышка)

Сравним с массивами. В той задаче нас спасал заход «с конца»: у массива есть индексы, можно встать в любую ячейку, в том числе в хвост с заглушками. У связного списка ни того, ни другого: индексов нет, назад по нему не пройти. Зато у списка есть то, чего не было у массива, — мы свободно перецепляем ноды, меняя ссылки `next`. Поэтому здесь другой приём.

Проблема первого элемента. Идём с начала, сравниваем головы двух списков, меньшую берём в результат. Но куда её присоединить в самый первый раз? Головы результата ещё нет — её как раз предстоит выбрать. Городить отдельное «если это первый элемент, то…» не хочется: лишний код, лишние ошибки.

Ключевая идея: dummy-узел. Заводим одну фиктивную ноду-пустышку `dummy` и держим на ней хвостовой указатель `tail`. Мы всегда цепляем очередную ноду за `tail`, даже самую первую — так исчезает особый случай для головы. А в конце просто вернём `dummy.next`: это и есть настоящая голова слитого списка.

Алгоритм:

1️⃣ Создаём `dummy` и `tail = dummy`.
2️⃣ Пока обе головы не пусты: сравниваем `list1.value` и `list2.value`, меньшую ноду цепляем за `tail` (`tail.next = ...`), двигаем `tail` и указатель того списка, откуда взяли.
3️⃣ Один из списков кончился — оставшийся хвост второго уже отсортирован, цепляем его целиком за `tail` одной ссылкой.
4️⃣ Возвращаем `dummy.next`.

Код на Python:

```python
def merge_two_lists(list1, list2):
    dummy = Node(0)     # нода-пустышка перед началом результата
    tail = dummy

    while list1 and list2:
        if list1.value <= list2.value:
            tail.next = list1
            list1 = list1.next
        else:
            tail.next = list2
            list2 = list2.next
        tail = tail.next

    tail.next = list1 if list1 else list2   # подцепляем оставшийся хвост
    return dummy.next
```

Код на Java:

```java
Node mergeTwoLists(Node list1, Node list2) {
    Node dummy = new Node(0);
    Node tail = dummy;

    while (list1 != null && list2 != null) {
        if (list1.value <= list2.value) {
            tail.next = list1;
            list1 = list1.next;
        } else {
            tail.next = list2;
            list2 = list2.next;
        }
        tail = tail.next;
    }

    tail.next = (list1 != null) ? list1 : list2;
    return dummy.next;
}
```

Пошагово на `list1 = 1 → 2 → 4`, `list2 = 1 → 3 → 4`:

• `1` vs `1`: равны, берём из list1 → результат `1`. list1 = `2 → 4`
• `2` vs `1`: меньше `1` из list2 → `1 → 1`. list2 = `3 → 4`
• `2` vs `3`: меньше `2` из list1 → `1 → 1 → 2`. list1 = `4`
• `4` vs `3`: меньше `3` из list2 → `1 → 1 → 2 → 3`. list2 = `4`
• `4` vs `4`: равны, берём из list1 → `1 → 1 → 2 → 3 → 4`. list1 пуст
• list1 кончился → цепляем остаток list2 (`4`) одной ссылкой → `1 → 1 → 2 → 3 → 4 → 4`

Ответ: `1 → 1 → 2 → 3 → 4 → 4` ✅

Сложность: `O(m + n)` времени — каждую ноду посещаем один раз. `O(1)` памяти — новых нод не создаём (кроме одной пустышки), просто перецепляем ссылки.

——

Сравнение двух слияний одной картинкой: в массивах структура жёсткая (непрерывная память, индексы), поэтому выкручивались направлением — шли «с конца». В списках структура гибкая (ссылки), поэтому выкручиваемся перецепкой ссылок и dummy-узлом. Один и тот же паттерн «два указателя», две разные реализации под две разные структуры данных — и понимать эту разницу как раз и проверяют на собесе.

А сам dummy-узел — это отдельный приём, который выручает всякий раз, когда голова списка может меняться (удаление из начала, вставка в отсортированный список). Запомните его, встретите ещё не раз.
