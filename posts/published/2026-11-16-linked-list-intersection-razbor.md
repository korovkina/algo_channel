👨🏼‍💻 Как обещала на вебинаре про связные списки, разбираем пересечение двух списков

📊 Материал среднего уровня

Условие: даны головы двух односвязных списков `head_a` и `head_b`. Нужно вернуть ноду, с которой списки сливаются в один, или `None`, если общих нод нет. Менять списки нельзя, циклов в них нет.

Пример:
- Вход: A = `4 → 1 → 8 → 4 → 5`, B = `5 → 6 → 1 → 8 → 4 → 5`, общая часть начинается с ноды `8`
- Выход: нода `8`

Ещё пример:
- Вход: A = `1 → 2`, B = `3`, общих нод нет
- Выход: `None`

Проверить решение можно тут: https://leetcode.com/problems/intersection-of-two-linked-lists/

❗️ Сначала главный подвох. Пересечение — это общая нода, а не одинаковое значение. В первом примере в обоих списках есть `1`, но это две разные ноды, которые просто хранят одно и то же число. Общая часть начинается с `8`: дальше у списков буквально одни и те же ноды. Поэтому сравниваем сами ноды (`p is q`), а не значения (`p.value == q.value`). На вебинаре это была одна из трёх частых ошибок: перепутать ноду и её значение.

Что приходит в голову первым:
• Для каждой ноды A пройти весь B. Это `O(m · n)` времени.
• Сложить все ноды A в хеш-сет, потом идти по B и вернуть первую ноду, которая есть в сете. Это `O(m + n)` времени, но `O(m)` памяти.

Хеш-сет — нормальный ответ, но интервьюер почти наверняка спросит: а без дополнительной памяти?

Паттерн: два указателя

Ключевая идея: до общей части списки разной длины, поэтому указатели, которые идут с одной скоростью, приходят к общей ноде в разное время. Уравниваем им путь: каждый указатель, дойдя до конца своего списка, перескакивает на голову чужого.

Почему это работает. Пусть у A своя часть длины `a`, у B своя часть длины `b`, а общий хвост длины `c`. Первый указатель проходит `a + c`, потом `b` и оказывается в начале общей части. Второй проходит `b + c`, потом `a` и тоже оказывается в начале общей части. Пути равны: `a + c + b = b + c + a`. Значит, туда они придут на одном и том же шаге.

А если пересечения нет? Тогда оба пройдут оба списка целиком и на одном шаге окажутся в `None`. `None is None`, цикл останавливается, возвращаем `None`.

Алгоритм:

1️⃣ Ставим `p` на голову A, `q` на голову B.
2️⃣ Пока `p` и `q` — разные ноды, двигаем каждый на шаг вперёд. Если указатель стоит в `None`, переводим его на голову другого списка.
3️⃣ Возвращаем `p`: это либо общая нода, либо `None`.

Код на Python:

```python
def get_intersection_node(head_a, head_b):
    p, q = head_a, head_b
    while p is not q:                  # сравниваем ноды, а не значения
        p = p.next if p else head_b    # дошли до конца — прыгаем на чужую голову
        q = q.next if q else head_a
    return p
```

Код на Java:

```java
Node getIntersectionNode(Node headA, Node headB) {
    Node p = headA, q = headB;
    while (p != q) {                   // для объектов == сравнивает ссылки
        p = (p != null) ? p.next : headB;
        q = (q != null) ? q.next : headA;
    }
    return p;
}
```

Пошагово на первом примере. Вот по каким нодам проходят указатели:

• `p`: `4 → 1 → 8 → 4 → 5 → None → 5 → 6 → 1 → 8`
• `q`: `5 → 6 → 1 → 8 → 4 → 5 → None → 4 → 1 → 8`

На 9-й позиции оба указателя стоят на `1`, но это разные ноды: `p` на единице из B, `q` на единице из A. Решение со сравнением значений вернуло бы здесь неверный ответ. На 10-й позиции оба стоят на одной и той же ноде `8`, это и есть ответ ✅

Сложность: `O(m + n)` времени, каждый указатель проходит не больше `m + n` нод. `O(1)` памяти, только два указателя.

❌ Частая ошибка в этом решении: перескакивать на чужую голову, когда `p.next` равен `None`, а не когда сам `p` равен `None`. Тогда указатели никогда не окажутся в `None` одновременно, и на непересекающихся списках цикл будет крутиться вечно. Проверьте свой код на втором примере: `1 → 2` и `3`.

——

Есть и третий способ без дополнительной памяти: посчитать длины обоих списков, сдвинуть указатель длинного списка вперёд на разницу длин, а потом идти обоими указателями вместе до первой общей ноды. Тоже `O(m + n)` и `O(1)`, просто кода чуть больше. На собесе подойдут оба, но решение с перескоком на чужую голову красивее, и его легче написать без ошибок.
